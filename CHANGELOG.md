# Changelog

All notable changes to gocore. Format follows [Keep a Changelog](https://keepachangelog.com/);
gocore is pre-1.0, so a minor version may contain breaking changes. Each one lists a migration step.

## [Unreleased]

### Added
- `httpmw`: framework-neutral `net/http` middleware (`RequestID`, `Recovery`, `RequestLogger`, `CORS`) for Chi,
  `http.ServeMux` and any router built on `net/http`. The Gin middleware in `httpserver` now shares its CORS
  decision, request-ID validation and request-log format with it (behaviour unchanged).
- `iam/iamhttp`: `JWT` (bearer header or cookie) and `Casbin` middleware for `net/http`, the counterpart of `iamgin`.
- `httpmw.RequestLogger(httpmw.WithClientIP(fn))`: log a client IP resolved by your own trusted-proxy logic.

### Fixed
- `httpmw.Recovery` no longer turns `panic(http.ErrAbortHandler)` into a clean end of response: it closes the
  connection (HTTP/1.x) so a truncated body, for example from `httputil.ReverseProxy`, reaches the client as an error.
- The `httpmw` docs no longer suggest Chi's `middleware.RealIP`, which Chi deprecated because it lets any client
  choose the address that is logged and rate limited; they point to trusted-proxy resolution instead.

## [0.3.0] - 2026-10-28

### Changed (breaking)
- **`database` no longer imports any driver.** The core package connects through a `gorm.Dialector`
  and drivers live in sub-packages, so a service carries only the driver it uses (a Postgres-only
  service no longer vendors `go-sqlite3` or the MySQL driver).
  - Removed: `database.New`, `database.NewPostgres`, `database.NewMySQL`, `database.NewSQLite`.
  - Added: `database.Open` / `database.Connect` (take a dialector), `database/postgres`,
    `database/mysql`, `database/sqlite` (each with `New` and `Open`), and `database/anydriver`
    (`New` selects the driver from `Config.Driver`; it links every driver).
  - **Migration:**

    | Before | After |
    |---|---|
    | `database.New(ctx, cfg)` (driver known at compile time) | `postgres.New(ctx, cfg)` (or `mysql.New`, `sqlite.New`) |
    | `database.New(ctx, cfg)` (driver from config) | `anydriver.New(ctx, cfg)` |
    | `database.NewPostgres(ctx, cfg)` | `postgres.Open(ctx, cfg)` |
    | `database.NewMySQL(ctx, cfg)` | `mysql.Open(ctx, cfg)` |
    | `database.NewSQLite(ctx, cfg)` | `sqlite.Open(ctx, cfg)` |

    Import paths: `github.com/baby-hero-404/gocore/database/{postgres,mysql,sqlite,anydriver}`.

### Added
- `iam.JWTConfig.IDClaim` and `RolesClaim`: read the user id and roles from custom claim names
  (for example `userId`). Empty keeps the previous lookup (`sub`/`id`, `roles`/`role`).
- `iam.JWTConfig.TokenType`: `JWTSigner` writes it as the `typ` claim and `JWTValidator` rejects
  tokens whose `typ` differs. **Services that issue more than one kind of token (access and
  refresh) must set it on every signer and validator**, otherwise the tokens are interchangeable.
  Tokens issued without `typ` are rejected by a validator that has `TokenType` set, so enabling it
  signs users out once.
- `JWTSigner` also writes the configured `IDClaim` next to `sub`.

## [0.2.0] - 2026-10-28

### Changed (breaking)
- `httpserver.Server.Start` now takes a context: `Start(ctx)` blocks until the server fails or
  `ctx` is cancelled, then shuts down gracefully within `Config.ShutdownTimeout` (default 10s) and
  returns nil. **Migration:** call `srv.Start(ctx)`, usually with `signal.NotifyContext`.
- Mocks are generated by mockery (`make mocks`). Constructors take the test: `NewDatabase(t)`;
  expectations are available through `.EXPECT()`. Unmocked calls panic instead of returning zero
  values. **Migration:** pass `t`, set expectations, regenerate your own mocks if you embed ours.
- `stdres.FromError` no longer puts the text of unclassified errors (anything that is not a
  `*stderr.Error`) in the response: clients get `"internal server error"`. The real error is logged
  once with the request ID by `stdgin.Error` / `stdres.WriteError` (`stdres.LogUnclassified`).
  **Migration:** wrap errors you want shown with `stderr`; tests asserting raw messages must change.
- CORS: `"*"` in `AllowOrigins` answers with the literal `*` and never with credentials; only
  origins listed explicitly receive `Access-Control-Allow-Credentials`. Origins that match nothing,
  and requests without an `Origin` header, receive no CORS headers. **Migration:** list origins
  explicitly when `AllowCredentials` is set.
- `lock.Acquire` separates failures: contention is `CodeLockHeld` (409), an unreachable Redis is
  `CodeUnavailable` (503) and a cancelled context is `CodeTimeout` (504). It used to report every
  failure as `CodeLockHeld`.
- `iam.JWTValidator` enforces `SigningMethod`, `Issuer`, `Audience` and `ClockSkew` when they are
  set (they were ignored before). Tokens that do not match are rejected.
- Secret fields are excluded from JSON: `database.Config.DSN`, `cache.Config.Password`,
  `iam.JWTConfig.Secret`, `sentry.Config.DSN` (`json:"-"`). Configuration loaded through
  `env.Load` (mapstructure) is unaffected.
- `database.WrapError` maps deadline and network timeouts to `CodeTimeout` (504).
- `X-Request-ID` from clients is reused only if it is at most 128 characters from
  `A-Z a-z 0-9 - _ . : / + = @`; otherwise a UUID replaces it.

### Added
- `database/pagination`: cursor (HMAC-signed, multi-column keyset) and offset pagination.
- `monitor/prom`: real in-flight request gauge (`gocore_http_in_flight_requests`).
- `stdlog.ContextWithRequestID`, `stderr.FromPanic`, `stdres.LogUnclassified`.
- Quality gates: golangci-lint, gitleaks, govulncheck (`make vuln`), architecture tests, coverage
  ratchet (`make verify`).
