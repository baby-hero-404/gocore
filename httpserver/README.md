# Package `httpserver`

`httpserver` wraps Gin with production-ready base middlewares: panic recovery (mapping into `stdres.Envelope`), request tracking (`X-Request-ID`), structured latency logging with `stdlog`, CORS handling, and graceful shutdown.

## Features

- **Interface-Driven & Function-File Layout**: Exposes `httpserver.Server` interface with dedicated function files (`spec.go`, `new.go`, `option.go`, `start.go`, `shutdown.go`, `config.go`, `middleware.go`).
- **Standardized Panic Recovery**: Intercepts panics, logs stack trace securely via `stdlog`, and outputs standard HTTP 500 error envelope (`stdres.Envelope`) without terminating the process.
- **Trace Propagation**: Attaches unique `X-Request-ID` to request context and headers.
- **Structured Latency Logging**: Logs HTTP method, path, status, latency, and client IP on every request.
- **Graceful Shutdown**: Wraps `http.Server.Shutdown(ctx)` to drain in-flight connections cleanly.
- **Downstream Unit Testing**: `httpservermock.Server` generated by mockery (`make mocks`).

## Usage

```go
package main

import (
    "context"
    "log"
    "os"
    "os/signal"
    "syscall"

    "github.com/baby-hero-404/gocore/httpserver"
    "github.com/baby-hero-404/gocore/stdres"
    "github.com/gin-gonic/gin"
)

func main() {
    srv := httpserver.New(httpserver.Config{
        Port: 8080,
    })

    // Register routes
    srv.Engine().GET("/health", func(c *gin.Context) {
        stdgin.OK(c, map[string]string{"status": "ok"})
    })

    // Start blocks until the server fails or ctx is cancelled (SIGINT/SIGTERM here),
    // then shuts down gracefully within Config.ShutdownTimeout (default 10s).
    ctx, stop := signal.NotifyContext(context.Background(), os.Interrupt, syscall.SIGTERM)
    defer stop()
    if err := srv.Start(ctx); err != nil {
        log.Fatalf("server error: %v", err)
    }
}
```

> Gin's run mode is process-wide, so `httpserver` does not set it. Set `GIN_MODE=release` or call `gin.SetMode(gin.ReleaseMode)` in `main`.

## CORS and request IDs

* A request is given CORS headers only when it carries an `Origin` header. An origin listed in `AllowOrigins` is echoed back (with `Vary: Origin`, and `Access-Control-Allow-Credentials: true` if `AllowCredentials` is set).
* A `"*"` entry answers any other origin with the literal `*` and **never** with credentials; to allow credentialed cross-origin calls, list the origins explicitly. Origins that match nothing receive no CORS headers.
* `X-Request-ID` is reused only if it is at most 128 characters from `A-Z a-z 0-9 - _ . : / + = @`; otherwise a fresh UUID replaces it.
